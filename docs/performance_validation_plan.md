# 移动端性能与兼容性验证计划

本计划用于确认荞麦籽质检模型在移动设备（优先高通 Snapdragon 系列）上的推理表现与稳定性，确保在发布 Android Demo 之前具备可量化的验收标准。

## 1. 测试设备矩阵

| 平台 | 机型示例 | Android 版本 | NNAPI 驱动版本 | 备注 |
| ---- | -------- | ------------ | --------------- | ---- |
| Qualcomm 高端 | Snapdragon 8 Gen 2 开发板/量产机 | 13+ | 厂商默认 | 目标主平台，优先验证 NPU 路径 |
| Qualcomm 中端 | Snapdragon 7 Gen 1 | 12+ | 厂商默认 | 检查 NPU 与 GPU 的兼容性 |
| Intel x86 参考 | Windows/Linux + ONNX Runtime | N/A | N/A | 用于对比 CPU/GPU 基线性能 |
| （可选）联发科 | Dimensity 9200 | 13+ | 厂商默认 | 仅在后续扩展时纳入 |

> **说明**：若 NNAPI 在某机型不可用，可记录驱动信息并回退至 GPU (Vulkan) 或 CPU。

## 2. 模型版本与输入配置

| 模型 | 输入尺寸 | 备注 |
| ---- | -------- | ---- |
| PP-YOLOE+ L | 800×800 | 主推版本，如遇内存超限需考虑瘦身 |
| PP-YOLOE+ M | 640×640 | 备选轻量模型，用于性能对比 |
| FP16 版本 | 同上述 | 通过 Paddle/ONNX 导出半精度版本 |
| （可选）INT8 量化 | 640×640 | 后续量化实验使用 |

## 3. 指标与采样方法

1. **冷启动时间**：App 启动后首次完成一次推理的耗时。重复 5 次取平均。
2. **单帧耗时（e2e）**：从摄像头捕获帧到 UI 绘制完成的时间，记录平均值、P90、P99（≥200 帧）。
3. **推理引擎耗时**：仅模型 `session.run` 部分的时间；区分 NNAPI / GPU / CPU。
4. **功耗/温升（可选）**：借助厂商工具或第三方应用记录 5 分钟运行的功耗变化。
5. **显存/内存峰值**：使用 Android Studio Profiler 或平台工具在 1 分钟运行期间记录峰值。
6. **精度回归**：针对标准测试集（≥200 张），比较移动端与桌面端的 AP@0.5 与召回率。允许误差不超过 ±0.5%。

## 4. 测试步骤

1. **环境准备**
   - 安装带 NNAPI 支持的 ONNX Runtime AAR。
   - 将 `sandbox_scripts/onnx_sanity_check.py` 跑通，确认 ONNX 与 Paddle 输出一致。
   - 在设备上开启开发者选项，允许 USB 调试。
2. **基线采集**
   - 在桌面端（Intel CPU/GPU）运行 Python 版推理流程，记录耗时与精度，用作对照。
3. **NPU 优先验证**
   - 在目标机上运行 Demo，确保 `OrtSession` 使用 NNAPI provider。
   - 记录指标（单帧耗时、成功帧率、内存）。
   - 若出现 `NOT_IMPLEMENTED` 等错误，自动切换到 GPU/CPU，并在日志中记录异常。
4. **回退路径**
   - 强制禁用 NNAPI（在设置或构建配置中），验证 Vulkan/CPU 路径是否稳定。
5. **压力测试**
   - 连续运行 10 分钟，观察热量与内存。若有内存泄漏或帧率持续下降，记入缺陷单。
6. **精度对比**
   - 将移动端的检测结果（可导出 JSON 或日志）与桌面端做对比，对齐框坐标与置信度。

## 5. 验收门槛

| 指标 | 基准需求 | 说明 |
| ---- | -------- | ---- |
| 单帧总耗时 | ≤ 120 ms（NNAPI），≤ 200 ms（GPU），≤ 350 ms（CPU） | 保障实时性 |
| 平均 FPS | ≥ 8 FPS（NNAPI），≥ 5 FPS（GPU） | UI 流畅度 |
| 内存峰值 | ≤ 1.8 GB | 包含应用 + 推理引擎 |
| 精度差异 | AP@0.5 差异 ≤ 0.5% | 与桌面端对比 |
| 稳定性 | 连续运行 10 分钟无崩溃、无严重掉帧 | 可靠性 |

若未达到指标：

- 优先检查预处理与后处理耗时，考虑移除冗余复制。
- 评估换用 PP-YOLOE+ M/S 或减少输入尺寸。
- 尝试启用 FP16 或进行轻量化/量化。

## 6. 结果记录模板

建议在 `docs/perf_results/` 下建立按日期分组的 CSV/Markdown 文件，内容包括：

- 设备信息（Soc、Android 版本、NNAPI 驱动号）
- 模型版本与输入尺寸
- 运行模式（NNAPI/GPU/CPU）
- 关键指标数值（冷启动、平均耗时、P90、FPS、内存）
- 精度差异与备注（包含异常日志链接）

此模板可用于后续自动化回归，确保每次模型或引擎升级后都有对比依据。
